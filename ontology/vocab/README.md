# geo-lod controlled vocabularies

Shared SKOS schemes that all geo-lod data strands point to instead of holding
their own copies. Maintained here, in `GeoScience-FAIRification-LOD`; the
`wdttest-*` / `wd-*` repositories consume them through their IRIs.

## IRI pattern

    http://w3id.org/geo-lod/vocab/<scheme>/

One path segment per scheme, always with a trailing slash, always `http://`.
Concepts sit directly under it:

    http://w3id.org/geo-lod/vocab/mis/MIS_5e

This is the second of the three levels agreed for geo-lod IRIs: classes and
properties stay flat under `http://w3id.org/geo-lod/`, controlled vocabularies
live here, instance data goes into one branch per strand (`…/epica/`,
`…/sisal/`, `…/ci/`, `…/elsa/`).

## Schemes

| Scheme | Path | File | Status |
|---|---|---|---|
| Marine Isotope Stages | `…/vocab/mis/` | `mis.ttl` | published |
| Marker tephras | `…/vocab/tephra/` | — | reserved, filled with the ELSA strand |

## mis.ttl

Generated by `ontology/build_mis_vocab.py` from the primary sources in
`data/raw/mis/`. Do not edit by hand — the file is rewritten on every pipeline
run.

The same run writes two tables to `dist/`, carrying exactly the values the RDF
carries:

| File | Shape |
|---|---|
| `dist/mis_stages.csv` | one row per concept, leading values only: `begin_ka`, `end_ka`, `peak_ka`, `climate_mode`, `leading_source`, `derived` |
| `dist/mis_assignments.csv` | one row per assignment: stage, property, value, source, status — both readings side by side |

Figures and age-axis code read the first; the second is the lossless form for
anything that needs to see the disagreement. Nothing downstream recomputes a
boundary.

The leading scheme is Railsback et al. (2015): its stages and lettered
substages are what every MIS assignment elsewhere in geo-lod refers to. It
covers 0 to 1013.1 ka BP. Older concepts come from the LR04 boundaries of
Lisiecki & Raymo (2005), the only source reaching back that far; `dct:source`
on each concept records which source defines it.

The two sources disagree, and that disagreement is kept rather than resolved.
LR04 puts the 5/6 boundary at 130 ka, Railsback puts 5e/6a at 132.2 ka. Each
reading is its own `geolod:MISAttributeAssignment` with its own `dct:source`,
so a query can ask for either or compare both.

Which one applies where is stated in the data, not left to the consumer. Every
assignment carries `geolod:assignmentStatus`, either `geolod:LeadingAssignment`
or `geolod:AlternativeAssignment`, and every concept names its
`geolod:leadingSource`. Railsback leads wherever it reaches; beyond its
coverage LR04 leads; where only one source provides a property at all, such as
the LR04 excursion peaks, that one leads. Filtering on
`geolod:LeadingAssignment` therefore gives one consistent age axis --
Railsback through the Quaternary, LR04 in deep time -- without the consumer
having to know where the coverage ends. The materialised
`geolod:beginAgeKaBP` and `geolod:endAgeKaBP` on the concept follow the same
rule.

    SELECT ?stage ?age WHERE {
      ?a crm:P140_assigned_attribute_to ?stage ;
         crm:P177_assigned_property_of_type geolod:PeriodBeginning ;
         geolod:assignmentStatus geolod:LeadingAssignment ;
         crm:P141_assigned/time:numericPosition ?age .
    }

The coverage limit of Railsback et al. (2015) is data as well:
`geolod:coverageOldestAgeKaBP` on `mis:source_railsback2015`, currently
1013.1 ka BP.

Ages are given twice: as `geolod:ageKaBP` for direct querying and as a
`time:TimePosition` with `time:numericPosition` and `time:hasTRS`, pointing at
the reference system of the source in `ontology/trs.ttl`.

The warm/cold classification follows the parity convention, odd stages warm
and even stages cold, and carries Railsback et al. (2015) as its reference.
It applies to numbered stages only; the lettered Pliocene stages of LR04 are
left unclassified. MIS 3 carries a note: earlier geo-lod figures rendered it
as an interstadial, which the convention does not support.
